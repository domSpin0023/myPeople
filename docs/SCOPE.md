# Scope

## Initial scope statement

MyPeople stores and represents people in relation to the user. Fields that are connected to each person will help the user to engage in works of love related to that person.

## Scope ideas

- **Data stored is user-based.** The database stores users as individual entries. There are two kinds of user data: **Core** and **Perspective**.
  - **Core** is a user's self-proclaimed information.
  - **Perspective** is any data meant to be curated by another person in relation to one's core data.
  - Details and how they are stored: [CORE-AND-PERSPECTIVE.md](CORE-AND-PERSPECTIVE.md).
- **Several ways of representing relationships:** all relations, groups (family, friend groups, church, classes, others), and locations.
- **Connectors to other apps.** Let other apps do the work; myPeople is the beacon. Pinterest, Google Calendar, wellness apps and other personalized applications all find a common interface here: a person's core data (and, with consent, what others know of them) is the shared point they connect to, instead of each app rebuilding its own picture of the people you love.
- **AI agents that listen to the user's microphone input**, to reduce time spent on screen.
- **Peer-accountability features**, such as screen-time management. For example, a user can send another user a notification request asking for more screen time.

## Restrictions / scope limitations (technical or ethical)

- **Social interaction is meant to curate real-life interaction.** The app should not substitute for relationship.
- **Reduced gamification.** Spend as little time on the app as possible.
